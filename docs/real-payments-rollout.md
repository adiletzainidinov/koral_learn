# Реальная база семей и платежей — план безопасного запуска

Статус: **не подключено к production**. Пока сайт использует Zustand/localStorage и тестовые данные.

## Что проверено
- Репозиторий `adiletzainidinov/koral_learn`, ветка `main`.
- Сайт Vercel `koral-learn`: переменные окружения Supabase отсутствуют.
- Проект Supabase `koran-academy` существует, но **не доказано**, что он предназначен для QuranLearn. Не применять SQL без подтверждения.
- Текущие данные в localStorage могут содержать пользовательские записи. Не очищать их до резервного экспорта.

## Этапы
1. Подтвердить целевой Supabase проект и владельца Auth; проверить защищённый вход.
2. Сохранить резервную копию текущих данных браузера на устройстве администратора.
3. Применить `supabase/migrations/20261122_ql_real_family_payments.sql` к подтверждённому проекту; проверить RLS и индексы.
4. Реализовать защищённый UI и операции: создание семьи, выбор в «Поддержка», ввод платежей и комментариев, итог/остаток. Для транзакций — только новые записи; исправления через сторно.
5. Проверить запись и чтение после обновления и на другом устройстве. Убедиться, что demo seed не восстанавливает тестовые семьи.
6. Только после этого переключить production, удалить **лишь тестовые** семьи и платежи; остальные разделы не затрагивать.

## Учёт
- Суммы — целые сомы.
- Бронь — статус; она не является полученным платежом без транзакции.
- Возврат/исправление — отдельная отрицательная операция, исходная сохраняется.
- Доступ по RLS ограничен owner_id.
- Дамп базы и периодические резервные копии — обязательны до ввода реальных платежей.
